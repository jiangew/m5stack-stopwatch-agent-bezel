# Home IMU 交互试验

设计日期：2026-10-15；实机记录更新：2026-10-16。基线：`259f307`。分支：`codex/home-imu-pilot`。

这是单独选择的试验固件，默认发布环境不启用 IMU 交互。本文中的参数和目标不代表已完成实机验收。

## 体验

- 首页进入后先保持静止约 1.5 秒，建立当前姿态基准。
- 拿起：运动持续达到判据 60ms 后，角色从休息姿势恢复正常大小；自动熄屏时可唤醒。电源键主动休眠不被动作唤醒。
- 倾斜：角色左右旋转最多 8°、横向最多 10px、纵向最多 8px；保留点按动作的优先级。IMU 不触发换角色、切工作区或 Mac 操作。
- 放稳：低运动持续 1.5 秒后，角色缩小 5%、下移 4px，停在静态休息姿势；按原有电源策略稍后变暗/休眠。手持不动也可能被识别为放稳。
- 首页同时按住两颗侧键 2 秒，切换 IMU 开/关；每次按住只切换一次。关闭时冻结当前姿态，便于保持静态屏幕像素一致进行 A/B；状态从诊断查看。普通单键仍保持既有首页行为。
- 触摸、振动、侧键、电源操作期间，以及结束后的 250ms 内暂停并重新建立基准，避免自触发。切出首页、传感器异常或超过 120ms 的采样间隙也重新建立基准。
- 目标采样周期 20ms；实际周期受 I²C、渲染与同步 BLE RPC 影响，诊断记录最大间隙。画面变化最多约 30fps；静止姿态不持续重绘。自动休眠保留既有 PSRAM 图像缓存以降低再唤醒解码开销。

IMU 只能观测加速度和角速度，不能证明手离开桌面、测绝对位置或区分桌面静止/手持静止。极慢的平移可能无法识别；低速倾斜偏离基准超过 8°可以触发。首版方向已获用户体验确认；阈值的场景适用范围和噪声表现仍需要更多实机数据。

## 构建与回滚

```sh
pio run -e m5stack-stopwatch
HOMEBREW_PREFIX=/opt/homebrew pio run -e native-preview
pio run -d usb-mic -e m5stack-stopwatch-home-imu
ruby simulator/robot_home_imu_main_test.rb
```

试验环境继承现有纯输入 USB 麦克风目标，不改变 USB 描述符、配对身份、Companion 或认证。仅 IMU 试验环境响应 `device.imu`；该 RPC 是 control-only，不建立/续租可信 host 身份。配套 Companion 仍使用现有版本。

烧录前按 AGENTS.md 确认实物 C152 和准确串口，确认[官方出厂恢复路径](https://docs.m5stack.com/zh_CN/guide/stopwatch/restore_factory)；读取当前 Flash 作为回滚副本，读取并校验分区表/NVS/OTA 元数据。只写 `0x10000` 的 application binary，禁止使用 factory 合并镜像覆盖现有配置。回滚优先使用该设备的 app0 原始副本。副本仅放本地 ignored artifacts。

## 诊断采集

```sh
swift -module-cache-path /private/tmp/home-swift-cache scripts/hid_rpc_probe.swift --self-test
swiftc -module-cache-path /private/tmp/home-swift-cache scripts/hid_rpc_probe.swift -o /private/tmp/home-imu-probe
/private/tmp/home-imu-probe --imu-status
/private/tmp/home-imu-probe --imu-watch 600 artifacts/imu-static.jsonl
```

采集程序只匹配一个既有 vendor HID 设备，不包含设备地址/账号/内容。输出文件必须不存在，避免覆盖已有试验记录。实际设备权限、连接与响应需要实测；USB-mic 运行态没有普通串口。

记录含设备毫秒时钟、最新六轴数据、阶段（0校准/1静止/2拿起）、动作计数、采样间隙、I²C 读取用时、画面提交用时、电压、电量和亮度。事件（0无/1拿起/2放稳）的 `qualifying_at_ms → event_at_ms` 是算法持续判定时间；`event_frame_ms` 是检测事件至 framebuffer 提交完成，**不是动作实际开始到 OLED 发光的端到端延迟**。`pose_frame_ms` 是第一次未呈现姿态变化至帧提交，合并多次变化；物理触摸动画期间该值可能延长。

诊断只保留最新样本和累计计数，不是 50Hz 原始连续录制。2Hz 轮询会增加 BLE 开销；误触总数可由计数差得到，但不能重建全部传感器轨迹。重复轮询时必须验证采样间隙未超过 120ms；若超过，降低轮询频率并报告诊断扰动。测功耗时不持续轮询，以免把诊断流量计入正常交互消耗。

## 验收与数据记录

先拍摄/记录板放置方向，平放稳定 2 秒，检查 available=true、phase=1、errors 不增长。若初始化失败或数据不合理，先排查传感器，不继续解释交互结果。

| 试验 | 操作和分母 | 报告内容 | 暂定目标 |
| --- | --- | --- | --- |
| 静置误触 | 无触摸/振动，桌面静置 10 分钟 | 非预期拿起次数/10分钟；不是按样本数稀释的比例 | 0次 |
| 干扰误触 | 30次点击设备、30次轻敲桌面、30次旁边键盘操作；每次间隔至少2秒 | 按场景分别记录误触次数/30次 | 各场景≤1/30 |
| 拿起/放稳 | 30轮：静止2秒→拿起→倾斜→放稳2秒；保持可见视频或人工标记 | 命中/30、漏检/30、额外触发、放稳耗时 | 拿起≥29/30；放稳1.5–2秒 |
| 倾斜 | 左右各15次，含缓慢/正常两种速度 | 方向、幅度、抖动、误差、姿态更新延迟 | 可见跟随；物理P95≤150ms |
| 拿起响应 | 至少30次，高帧率视频同时拍到手和屏幕 | 动作起始到首个反馈的P50/P95/最大值；单列检测和提交延迟 | 物理P95≤200ms |
| 输入回归 | 点按、上/下/右换角色、左滑工作区、电源单/双击 | 独立确认各行为；不因动作发送Mac事件 | 原有行为正常 |
| 链路/音频回归 | USB枚举、短录音、BLE/HID状态RPC、工作区操作 | 按层分别记录 | 无新增断流/断连 |

P95 使用排序后 ceil(0.95*n) 对应样本。仅合成样本/固件时钟不可以声称已达到物理响应目标。误触率需要人工/视频真值：不能把所有事件都自动认作误触，也不能把未触发当成漏检而没有动作分母。

## 耗电验证

当前固定版本 M5Unified 的 `getBatteryCurrent()` 对 C152 不提供测量，默认返回0；诊断明确输出 `current_ma: null`。不得将其写成0mA，也不得从电量百分比短期不变推导零耗电。

优先用外部电流/功率仪表：相同供电、电池充电状态、亮度、BLE连接、音频流状态、角色和静态像素，IMU开/关各测三个稳定60秒窗口。短按后等待至少5秒恢复稳定再测；功耗窗口内不轮询诊断。报告平均/峰值电流和积分能量，以及两组差值。USB输入含充电电流，不能冒充电池放电电流。对交互状态另外使用相同动作序列测量总能量，区分轮询成本和渲染/唤醒成本。

没有仪表时，断USB、电池供电，固定相同起始电量/亮度/连接/音频状态，分别进行至少60分钟的开/关重复试验，记录起止电压、电量及休眠驻留时间，只称粗略续航对比，不能据此报告精确mA或mWh。

## 当前结果

- 合成数据：600秒有界静止噪声、30个孤立短脉冲无拿起；持续运动60ms判定；慢倾斜、放稳、防抖、坏样本、间隙、重置与时钟回绕通过。此结果不代表实机误触率。
- 原生回归：21个C++测试通过，另以试验宏验证诊断RPC为control-only；实际固件适配函数测试覆盖错开按键的A/B切换、被消费的唤醒触摸、静默期、工作区/电源边界和IMU不可用。
- 既有实际代码回归：Home手势、角色回应、工作区启动/输入隔离、Codex像素绘制测试通过；Swift诊断脚本self-test通过。
- 构建：默认固件、普通USB-mic固件、IMU试验固件、原生预览均已成功。原生预览存在既有M5GFX VLA/空符号归档警告。
- 原生预览：`artifacts/imu-pilot/home-imu-demo.gif` 与 contact sheet 使用同一检测器、图像缓存和渲染代码，输入为合成传感器序列。
- 代码复核：两个P2输入/功耗对比边界问题已由失败→通过的实际适配函数测试覆盖；独立复核未发现剩余重要问题。
- 2026-10-16 首版试验应用 `fe28100` 已写入 `app0/0x10000`。应用 SHA-256 为 `5bdd3ed9026ac8f15e5074bac9d6f79250f87ddb815382e73262f77d544b0bfe`；完整16MB备份通过设备端摘要校验，写入后应用摘要与独立ROM验证通过，前64KB保护区逐字节不变。RTS复位未退出下载态，后用标准看门狗复位恢复运行；USB与BLE/HID诊断均恢复。
- 实机首次诊断：IMU available=true、phase=1、errors=0；3分钟记录359个快照，包含1次拿起与1次放稳事件。拿起持续判定60ms、至帧提交65ms；放稳持续判定1554ms、至帧提交66ms。125ms是拿起首次合格传感器样本至提交的设备内部时间，不是物理动作至OLED发光的端到端延迟，也不足以给出P95。
- 该段诊断轮询开启时实际读取速率约31.8Hz，平均I²C读取769µs、最大1542µs、最大采样间隙95ms、读取错误0。不能把设定的50Hz写成实测50Hz。随后的约5分钟观察新增事件0、读取错误0；未获得人工静置/动作真值，不能将其直接换算为正式误触率。
- USB麦克风回归：3.221秒、154624帧、48kHz单声道16-bit；断点、长零段、重复块和削波均为0，临时音频已删除。该检查不代表长期音频可靠性或全部Agent控制已验收。
- 通用坐标模型的竖直轨迹检查曾产生交换pitch/roll映射的候选 `7ba4789`，其测试、构建和复核通过，**未部署**。随后用户确认首版三轮均有反馈且方向自然；真实板载IMU与屏幕坐标尚未标定，不能将通用模型的轴定义直接当成实物。因此保留首版已获实机确认的映射，代码恢复到 `fe28100` 的检测器/预览，候选仅留在Git历史供后续对照。
- 2026-10-16 用户确认：三轮拿起、左右倾斜、放稳均有反馈，方向自然。随后独立读取累计拿起4、放稳4、errors=0；三轮发生在前述两段采集结束后，不能用那两段日志计算三轮命中率。
- 后续动作采集开始后，用户明确表示不需要完成30轮、当前轮数足够且反馈正常，因而结束追加动作。实际动作分母未确认，不能报告30轮命中率或漏检率。两段日志累计758个快照，首尾约640.64秒，计数从拿起4/放稳4变为拿起12/放稳8，即新增8/4、读取错误新增0；这属于检测器计数，不能直接等同于真实动作数量。日志出现重新校准及短暂暂停，拿起/放稳计数不一的具体原因尚未逐轮确认。
- 该次采集首段2Hz轮询因一条诊断响应JSON解析错误中止，约127.83秒没有快照，随后改用本地1Hz采集副本恢复；没有修改设备固件。累计最大采样间隙从95ms增至137ms，超过120ms重校准阈值。降低轮询后该累计最大值未进一步增加，但累计最大值不能证明此后所有间隙都小于120ms。
- 已捕捉8个拿起、4个放稳事件的内部时序：拿起持续判定60–89ms、检测至帧提交65ms；首次合格样本至提交P50=125ms、P95=154ms（n=8）。放稳持续判定1520–1529ms、再65–66ms提交，合计1585–1594ms（n=4）。这些是设备内部事件时序，**不是物理动作开始至OLED发光的端到端P95**。姿态快照范围为旋转−8°至8°、横向−10px至10px、纵向0至8px；方向自然来自用户反馈，未用快照推导角度精度。
- 用户确认设备放稳后，单独完成10分钟受控静置：有效首尾跨度600.80秒、600个1Hz快照，采集正常结束；拿起12→12、放稳8→8、读取错误0→0，即非预期拿起 **0次/10分钟**。快照中的IMU始终available=true、active=true、phase=1；亮度按既有策略从120降为24，实际传感器读取速率约32.72Hz。累计最大间隙仍为137ms、未增加。该结果仅覆盖当前一台设备和本次桌面环境，不能外推为所有场景零误触；轻敲桌面、键盘、点击设备等干扰试验未执行。
- 本轮结论：拿起／倾斜／放稳的体验获用户确认，桌面10分钟静置目标通过；保留已部署首版，未追加烧录。固定轮数命中/漏检率、逐轮计数不一致原因、物理P95延迟和干扰场景误触仍未量化。用户已明确选择本轮先验证交互，耗电标为待仪表实测。
