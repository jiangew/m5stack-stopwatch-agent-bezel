# StopWatch 极轻短震候选

用户要求降低整体震动强度，并将震动产生的声音尽量降低。按“减弱”的表述默认保留轻微触感；完全关闭选项仍可由用户后续选择。下文保留首版设计历史，后续部署与调校见末节；不宣称稳定起转或达到物理最低噪声。

## 已核对基线

- 源码基线`9b32e20`，当前已验收应用`298f1c7b3ef4`保留。
- 按键／触摸强度176，滑动168，范围0..255；请求脉宽分别为按键42ms、一般触摸32ms、首页回应25ms、滑动40ms、唤醒20ms。
- 源码注明144档曾出现起转不稳定。160为本轮试验起点，不是已测得的可靠下限。
- `startHaptic`记录期限，主循环`updateHaptic`停止马达。长绘制可能跨过期限；关机路径另有70ms阻塞等待后才停止马达。
- 当前StopWatch PWM频率为2000Hz。本轮保持该频率及驱动、电源配置，仅调整强度、请求脉宽与停止优先级；震动声不是独立的扬声器音量。

## 候选规则

| 场景 | 强度0..255 | 请求脉宽 |
| --- | --- | --- |
| 首页回应与普通触摸 | 160 | 16ms |
| 页面／角色滑动 | 160 | 20ms |
| 物理按键 | 160 | 20ms |
| 唤醒反馈 | 160 | 12ms |
| 旅行关机确认 | 160 | 24ms |

不新增震动，不改变触发条件或次数。首页首个回应帧仍在震动开始前提交。若短震尚未结束，后续`drawScreen`保留重绘请求并返回，让主循环继续处理输入、音频和停止期限；马达停止后继续绘制。关机先结束任何旧脉冲，再画关机提示，确认脉冲24ms后显式停止，提示总等待仍为原来的550ms。

实施澄清：`shouldRedraw`跨循环保留，新的`latest.dirty`与待绘制请求合并；Agent状态变化检测仍仅由本次`latest.dirty`触发，避免等待绘制时重复处理事件。门控覆盖默认与USB-mic环境。普通触摸现有55ms按键等待拆为16ms、停马达、剩余39ms，按键按下／释放语义及程序等待总长保持；I2C调用实际耗时尚未测量。若新首页点击在旧短震期间被接受，先停旧脉冲，再提交本次首个回应帧，最后启动唯一的新16ms反馈。

保持角色、素材、动画、手势、电源触发、IMU检测／250ms保护、USB音频、Companion、配对及默认IMU启用方式。请求脉宽不是示波器测得的实际脉宽，仍受循环调度与I2C影响；稳定起转、手感及噪声以本机实测为准。最低可听噪声没有仪表结果，不能声称完全静音。

## 验证和交付

实际主函数回归验证强度与脉宽、一次触发、期限／wraparound、绘制延后但重绘不丢、65ms模拟绘制不拖长短震，以及旅行关机停止顺序与550ms等待。跑现有触摸／IMU组合及相关音频回归，构建默认、Home IMU和原生预览。独立复核后冻结app-only候选与完整摘要。新镜像仍需按AGENTS核对真实端口并确认后烧录，保留当前已验收镜像；本任务不自动合并或推送。

## 首版实测后的调校

首版`eb1a7fc`／`d30708d3b27d`已烧录、独立ROM校验及保护区比对通过；用户反馈“触感太弱，偶尔感觉不到”，未确认噪声结果。无法从主观反馈区分未起转与触感不可感知。后续候选仅回调震动档位：统一强度176，首页／普通触摸、滑动／按键及关机24ms，唤醒20ms；保留全部停止／绘制顺序、55ms按键等待及550ms关机等待。此调校以更可感知的短震为假设，不能宣称已稳定起转或噪声已达标，仍需新镜像确认后实测。前述160表为首版历史参数；当前源码以本节为准。

## 用户指定的76档试验

用户在176/255、24ms版实测后认可触感与声音，但报告IMU动作消失；桌面静止诊断为校准中，陀螺仪约6.5度／秒超过4度／秒门限，启动校零原因仍待静止重启验证。用户随后明确指定点击／滑动改为76/255、30ms。本轮只修改首页／普通触摸及滑动参数，实体按键保持176/255、24ms，唤醒20ms、关机24ms；不改IMU算法。76低于此前偶尔不可感知的160档，软件请求不证明马达起转、触感或声音，必须实机验证。新参数取代此前触摸／滑动候选值，其他既有停止／绘制顺序及等待不变。

## 用户指定的176／30ms试验

76/30ms版`d9201a2`／`0b6c31aadbde`已烧录；静止启动后陀螺仪约0.32度／秒，校准完成，用户确认动作恢复，计数3次拿起／3次放稳、读取错误0，但感觉不到震动。用户明确选择点击／滑动176/255、30ms。本轮只把触摸／滑动强度回调176，保留30ms及原有按键176/24ms、唤醒20ms、关机24ms，不改IMU算法。此节取代之前候选参数；新档位触感与声音仍需实机验收，静止重启恢复不等于实现自动零偏修复。
